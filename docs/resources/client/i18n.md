# 国际化与本地化（I18n and L10n）

I18n（Internationalization，国际化的缩写）是让程序能够支持多种语言的设计方式。L10n（Localization，本地化的缩写）是把文本翻译成用户语言的过程。Minecraft 使用 `Component` 实现二者。

## `Component`

`Component` 是一段带有 Metadata 的文本，Metadata 包括文本格式等内容。可以通过以下方式之一创建它（以下均为 `Component` 接口中的静态方法）：

| 方法         | 说明                                                                                           |
|----------------|-------------------------------------------------------------------------------------------------------|
| `empty`        | 创建空 Component。                                                                           |
| `literal`      | 使用给定文本创建 Component，直接显示文本而不进行翻译。          |
| `nullToEmpty`  | 传入 null 时创建空 Component，否则创建 Literal Component。                        |
| `translatable` | 创建可翻译 Component。给定 String 会被解析为翻译键（见下文）。 |
| `keybind`      | 创建包含给定 Keybind（已翻译）显示名称的 Component。                    |
| `nbt`          | 创建表示给定路径处 [NBT][nbt] 的 Component。                                    |
| `score`        | 创建包含 Scoreboard Objective 值的 Component。                                          |
| `selector`     | 创建包含给定 [Entity Selector][selector] 所选 [Entity][entity] 名称列表的 Component。      |
| `object`       | 创建包含任意 Font（例如 Atlas Sprite）的 Component。                               |

`Component.translatable()` 还提供一个接受 String 插值元素的 vararg 参数。它的工作方式类似 Java 的 `String#format`，但始终使用 `%s`，而不是 `%i`、`%d`、`%f` 或其他格式说明符，并在需要时调用 `#toString()`。

每个 `Component` 都可以通过 `#getString()` 解析。解析通常是惰性的，这意味着服务端可以指定一个 `Component` 并发送给客户端，各客户端再自行解析 `Component`（不同语言可能产生不同文本）。Minecraft 中的许多位置也可以直接接受 `Component`，并替你完成解析。

:::warning
绝不要让服务端翻译 `Component`。始终把 `Component` 发送到客户端，并在那里解析。
:::

### `MutableComponent`

所有构造出的 Component 通常都是 `MutableComponent`。`MutableComponent` 提供的方法可以添加新的兄弟 Component（附加到当前 Component 末尾），并设置文本的 [Style][style]。构造或修改 Component 时，应始终使用 `MutableComponent`。

### 文本格式

`Component` 可以使用 `Style` 设置格式。`Style` 是不可变对象，修改时会创建新的 `Style` 对象，因此可以只创建一次，再按需复用。

:::info
Style 只能通过 `MutableComponent` 上的方法设置，因此请务必确认 `Component` 是 `MutableComponent`。
:::

通常可以使用 `Style.EMPTY` 作为基础。多个 `Style` 可以通过 `Style#applyTo(Style other)` 合并；该方法返回新的 `Style`，优先采用调用 `applyTo()` 的 `Style` 中的设置；如果其中没有相应设置，才使用参数所传 `Style` 中的设置。随后可按如下方式将 `Style` 应用于 Component：

```java
MutableComponent text = Component.literal("Hello World!");

// 创建新样式。
Style blue = Style.EMPTY.withColor(0x0000FF);
Style greenShadow = Style.EMPTY.withShadowColor(0xFF00FF00);
// 样式使用类似 builder 的模式。
Style blueItalic = Style.EMPTY.withColor(0x0000FF).withItalic(true);
// 除了斜体之外，我们还可以将样式设置为粗体、下划线、删除线或混淆。
Style bold          = Style.EMPTY.withBold(true);
Style underlined    = Style.EMPTY.withUnderlined(true);
Style strikethrough = Style.EMPTY.withStrikethrough(true);
Style obfuscated    = Style.EMPTY.withObfuscated(true);
// 让我们将一些风格融合在一起！
Style merged = blueItalic.applyTo(bold).applyTo(strikethrough);

// 设置组件上的样式。
text.setStyle(merged);
// 将新样式合并到其中。
text.withStyle(Style.EMPTY.withColor(0xFF0000));
```

另一种更复杂的格式设置方式是使用单击和悬停事件：

```java
// 我们对于点击事件总共有8个选项，对于悬停事件总共有3个选项。
ClickEvent clickEvent;
HoverEvent hoverEvent;

// 单击时在默认浏览器中打开给定的 URL。
clickEvent = new ClickEvent.OpenUrl(URI.create("http://example.com/"));
// 单击时打开给定文件。出于安全原因，此无法从服务器发送。
clickEvent = new ClickEvent.OpenFile("C:/example.txt");
// 单击时运行给定的命令。
clickEvent = new ClickEvent.RunCommand("/gamemode creative");
// 单击时在聊天中建议给定的命令。
clickEvent = new ClickEvent.SuggestCommand("/gamemode creative");
// 单击时更改图书页面。与书籍屏幕上下文无关。
clickEvent = new ClickEvent.ChangePage("1");
// 将给定文本复制到剪贴板。
clickEvent = new ClickEvent.CopyToClipboard("Hello World!");
// 打开一个对话框 screen （假设我们有一些 Holder<Dialog> 对话框）
clickEvent = new ClickEvent.ShowDialog(dialog);
// 将标识符和有效负载发送到服务端（默认情况下，记录发送的操作和有效负载）
clickEvent = new ClickEvent.Custom(Identifier.fromNamespaceAndPath("examplemod", "custom"), Optional.empty());

// 悬停时显示给定组件。也可以格式化。
// 请记住，单击或悬停事件在悬停工具提示中不起作用。
hoverEvent = new HoverEvent.ShowText(Component.literal("Hello World!"));
// 悬停时显示给定堆栈模板的完整工具提示。
hoverEvent = new HoverEvent.ShowItem(new ItemStackTemplate(...));
// 悬停时显示给定实体的完整工具提示。
// 请参阅 EntityTooltipInfo 的可能构造器。
hoverEvent = new HoverEvent.ShowEntity(new HoverEvent.EntityTooltipInfo(...));

// 将事件应用到样式。
Style clickable = Style.EMPTY.withClickEvent(clickEvent);
Style hoverable = Style.EMPTY.withHoverEvent(hoverEvent);
```

甚至可以设置 Component 所使用的 Font：

```java
// 设置样式要使用的字体。
// 必须匹配可用的 FontDescription.Resource（位于 `assets/<namespace>/font/<path>.json`）

// 指向 `assets/minecraft/font/illageralt.json`
Identifier fontLocation = Identifier.withDefaultNamespace("illageralt");

// 将字体应用于样式
Style customFont = Style.EMPTY.withFont(new FontDescription.Resource(fontLocation));
```

:::warning
在 Style 中使用 `FontDescription.Resource` 以外的 Font Description 类型会抛出异常。要使用其他或自定义 `FontDescription`，请创建 `ObjectInfo`，并把它提供给带有 `ObjectContents` 的 Component。
:::

## 语言文件

语言文件是包含翻译键（见下文）到实际名称映射的 JSON 文件。它们位于 `assets/<modid>/lang/language_name.json`。例如，模组 ID 为 `examplemod` 时，美式英语翻译位于 `assets/examplemod/lang/en_us.json`。可以在[此处][mcwikilang]查看 Minecraft 支持的完整语言列表。

语言文件通常如下所示：

```json
{
    "translation.key.1": "Translation 1",
    "translation.key.2": "Translation 2"
}
```

### 翻译键

翻译键是翻译中使用的键。它们通常遵循 `registry.modid.name` 格式。例如，一个 ID 为 `examplemod`、提供名为 `example_block` 的 Block 的模组，很可能需要为键 `block.examplemod.example_block` 提供翻译。不过，基本上任何 String 都可以用作翻译键。

如果翻译键在所选语言中没有对应翻译，并且所选语言不是美式英语，游戏就会回退到美式英语（`en_us`）。如果美式英语中也没有翻译，翻译会静默失败，并直接显示原始翻译键。

Minecraft 中有些位置提供了获取翻译键的 Helper 方法。例如，Block 和 Item 都提供 `#getDescriptionId` 方法。对于 Item，不仅可以查询，还可以在需要时通过 `Item.Properties#overrideDescription` 更改。如果 Item 根据底层 [数据组件][datacomponent] 使用不同名称，可以在 `ItemStack` 上把 `CUSTOM_NAME` 数据组件设为所需的可翻译 Component，从而覆盖名称。`Item#getName` 还有一个接收 [`ItemStack`][itemstack] 参数的变体，用于设置 Item 的默认 Component。另一方面，`BlockItem` 通过调用 `Item.Properties#useBlockDescriptionPrefix` 设置 Description ID。`Identifier` 也提供 `toLanguageKey`，可以使用 Section 或 Registry 以及可选后缀构造翻译键。

:::tip
翻译键的唯一用途是本地化。不要把它用于游戏逻辑；游戏逻辑应使用 [Registry Name][regname]。
:::

### 翻译模组 Metadata

翻译文件可以通过以下键覆盖[模组信息][modstoml]的特定部分（其中 `modid` 应替换为实际模组 ID）：

|              | 翻译键                        | 覆盖内容                                                                   |
|--------------|----------------------------------------|------------------------------------------------------------------------------|
| 说明  | `fml.menu.mods.info.description.modid` | 也可以改为在 `[[mods]]` Section 中放置名为 `description` 的字段。 |

### Datagen

语言文件可以通过 [Datagen][datagen] 生成。为此，请扩展 `LanguageProvider` 类，并在 `addTranslations()` 方法中添加翻译：

```java
public class MyLanguageProvider extends LanguageProvider {

    public MyLanguageProvider(PackOutput output) {
        super(
            // 由 `GatherDataEvent.Client` 提供。
            output,
            // 你的模组 ID。
            "examplemod",
            // 要使用的区域设置。你可以针对不同的区域设置使用多个语言提供器。
            "en_us"
        );
    }
    
    @Override
    protected void addTranslations() {
        // 添加具有给定键和给定值的翻译。
        this.add("translation.key.1", "Translation 1");
        
        // 帮助程序可用于各种常见对象类型。大多数助手有两种变体： add() 变体
        // 表示对象本身，以及接受对象提供器的 addTypeHere() 变体。
        // 由于泛型类型擦除，提供器变体需要不同的名称。
        // 以下所有示例均假设存在所需类型的值作为提供器。

        // 添加方块翻译。
        this.add(MyBlocks.EXAMPLE_BLOCK.get(), "Example Block");
        this.addBlock(MyBlocks.EXAMPLE_BLOCK, "Example Block");
        // 添加物品翻译。
        this.add(MyItems.EXAMPLE_ITEM.get(), "Example Item");
        this.addItem(MyItems.EXAMPLE_ITEM, "Example Item");
        // 添加ItemStack翻译。这主要适用于具有 NBT 特定名称的物品。
        this.add(MyItems.EXAMPLE_ITEM_STACK.get(), "Example Item");
        this.addItemStack(MyItems.EXAMPLE_ITEM_STACK, "Example Item");
        // 添加实体类型转换。
        this.add(MyEntityTypes.EXAMPLE_ENTITY_TYPE.get(), "Example Entity");
        this.addEntityType(MyEntityTypes.EXAMPLE_ENTITY_TYPE, "Example Entity");
        // 添加生物效果翻译。
        this.add(MyMobEffects.EXAMPLE_MOB_EFFECT.get(), "Example Effect");
        this.addEffect(MyMobEffects.EXAMPLE_MOB_EFFECT, "Example Effect");
        // 添加标签键翻译。
        this.add(MyTags.EXAMPLE_TAG, "Example Tag");
        // 添加尺寸转换。
        this.addDimension(MyDimensions.EXAMPLE_DIMENSION_KEY, "Example Dimension");
        // 添加生物群落翻译。
        this.addBiome(MyBiomes.EXAMPLE_BIOME_KEY, "Example Biome");
    }
}
```

然后，像注册其他 Provider 一样，在 `GatherDataEvent.Client` 中注册该 Provider。

```java
@SubscribeEvent // 位于模组事件总线上
public static void onGatherData(GatherDataEvent.Client event) {
    // 添加数据包对象时，请先调用 event.createDatapackRegistryObjects(...)

    event.createProvider(MyLanguageProvider::new);
}
```
